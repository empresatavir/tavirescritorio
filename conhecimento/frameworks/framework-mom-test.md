# Framework Mom Test

## Definição
Sistema prático para conduzir conversas com clientes de forma que seja impossível coletar dados falsos. A premissa central: a maioria dos founders coleta falsos positivos porque faz as perguntas erradas (sobre sua ideia, sobre o futuro, sobre hipotéticos) e aceita elogios como validação. O Mom Test define regras, ferramentas e processo para extrair fatos reais sobre a vida dos clientes — a única fonte de dados que vale.

## Mecanismo

### Por Que as Conversas Normalmente Falham

Conversas com clientes parecem fáceis e são sistematicamente mal executadas. O problema não é malícia — é que a estrutura errada convida as pessoas a mentirem involuntariamente.

Quando você pergunta "você compraria isso?", a pessoa ativa um futuro hipotético de si mesma — mais otimista, mais disposta a pagar, mais resolvida do que será na realidade. Quando você mostra que está emocionalmente investido na ideia, as pessoas automaticamente ativam o modo protetor. O resultado: elogios calorosos que não predizem nenhuma compra futura.

Conversas ruins não são apenas inúteis. São ativamente prejudiciais: convencem o founder de que está no caminho certo, justificando over-investment de tempo e capital.

### As 3 Regras do Mom Test

**1. Fale sobre a vida deles, não sobre a sua ideia**
A conversa nunca menciona o que você está construindo. Você pergunta sobre problemas, workflows, frustrações, objetivos — tudo na vida deles. Quem controla o que é discutido controla quais dados coleta.

**2. Pergunte sobre especificidades do passado, não sobre opiniões sobre o futuro**
"Me conta a última vez que esse problema apareceu" acessa memória real. "Você compraria se existisse X?" acessa fantasia otimista. Passado concreto → dado real. Futuro hipotético → ruído.

**3. Fale menos, ouça mais**
"The more you're talking, the worse you're doing." Cada vez que você fala, você para de aprender e começa a potencialmente contaminar as respostas do outro.

### Os 3 Tipos de Dado Ruim (e como lidar)

Ver [[dados-ruins-customer-dev]] para detalhamento completo. Em resumo:

- **Elogios**: deflect, ignore, volte para os fatos
- **Fluff** (genéricos, hipotéticos, promessas futuras): anchor com "quando foi a última vez que isso aconteceu?"
- **Feature requests**: dig para entender a motivação por trás do pedido — não obedeça o pedido, entenda o porquê

### Compromisso como Validação Real

Ver [[compromisso-avanco]]. Um meeting só termina com sucesso quando o prospect avança para o próximo passo real — não quando ele diz coisas positivas. As 3 moedas de compromisso: tempo (próxima reunião com objetivos definidos), reputação (intro para decisor), dinheiro (pré-venda, depósito).

"Zombie leads" — prospects que continuam se reunindo e sendo positivos sem jamais decidir — são o maior sinal de que os meetings estão sendo mal conduzidos.

### Segmentação como Pré-condição

Ver [[segmentacao-cliente]]. Feedback inconsistente de múltiplas conversas não é ambiguidade do mercado — é sinal de que o segmento está muito amplo. O par who-where (quem exatamente + onde encontrá-los) é a unidade mínima de segmento utilizável.

### O Processo Completo

Ver [[processo-customer-dev]] para o processo antes/durante/após cada conversa. A estrutura mínima:
- **Antes**: definir as 3 grandes perguntas com o time
- **Durante**: aplicar o Mom Test, deflect bad data, push para compromisso
- **Depois**: revisar com o time, atualizar crenças, definir próximas 3 perguntas

## Aplicações Práticas

### Na Validação de Ideia de Negócio
- Conduzir 3-5 conversas com o segmento-alvo antes de escrever uma linha de código
- Focar exclusivamente em entender o problema e o workflow atual — sem mencionar a solução
- A conversa terminou com sucesso se você aprendeu fatos concretos sobre como a pessoa vive o problema

### Em Vendas Early-Stage
- Cada reunião de vendas é também uma oportunidade de aprendizado — começar com perguntas abertas antes de mostrar qualquer produto
- Não existe reunião que "correu bem" — ou avançou para próximo passo real ou não valeu
- Primeiros clientes são "loucos" no bom sentido: querem tanto o que você está construindo que compram antes de fazer sentido racional. Ver [[earlyvangelist]]

### No Diagnóstico de PMF
- Se o feedback de clientes é inconsistente, a primeira hipótese é segmento fuzzy — não produto ruim
- Quando os padrões começam a aparecer em 3-5 conversas com o mesmo tipo de pessoa, o segmento está correto

## Relação com o Vault

O Mom Test completa o framework de [[segredos-thiel]]: Thiel diz que toda empresa foi fundada sobre um segredo (uma verdade que o mercado não viu). O Mom Test é o método para *encontrar* esses segredos de pessoas — as verdades sobre o que clientes realmente querem, temem e toleram que não aparecem em pesquisas de mercado convencionais.

Os [[7-perguntas-negocio-thiel]] perguntam "o mercado quer isso?". O Mom Test é como você responde essa pergunta com dados reais ao invés de projeções.

## Contra-indicações
- O Mom Test é uma ferramenta de aprendizado, não de vendas. Aplicar as regras numa reunião de vendas pode parecer estranho — o timing importa
- "Keeping it casual" funciona bem em mercados onde o founder tem acesso natural ao cliente; em enterprise, alguma formalidade é inevitável
- Conversas com clientes não substituem testes de produto: mercado pode querer algo que é impossível de construir (product risk)
